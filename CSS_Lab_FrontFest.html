    1. Зачем учить CSS системно — и почему до Tailwind #

    Типичный путь: CSS учится «по ходу» копированием со Stack Overflow, стили множатся, !important побеждает !important, а потом приходит Tailwind — и кажется, что CSS знать уже не нужно. Это не так: Tailwind — это тот же CSS, записанный классами. flex, grid-cols-[repeat(auto-fill,minmax(15rem,1fr))], @container, has-[:checked]: — если вы не понимаете, что за ними стоит, вы будете перебирать классы наугад так же, как раньше перебирали свойства.

    2.3 Каскад, специфичность, наследование

    Когда к элементу подходят несколько правил с одним свойством, побеждает одно — по каскаду (раздел 3). Некоторые свойства наследуются от родителя (color, font-*, line-height), другие нет (margin, border, background). Ключевые слова inherit, initial, unset, revert, revert-layer управляют этим явно.

    2.4 Box model

    Каждый элемент — прямоугольник: content → padding → border → margin. box-sizing: border-box включает padding и border в width, и именно так ожидает большинство людей. Раздел 4.

    2.5 display

    Задаёт две вещи: как элемент ведёт себя снаружи (block или inline в потоке родителя) и как раскладывает детей (flow, flex, grid). display: flex — это «снаружи block, внутри flex»; inline-flex — «снаружи inline, внутри flex». display: none убирает элемент из раскладки, contents убирает сам бокс, оставляя детей.

    3. Каскад под капотом: происхождение, слои, специфичность, порядок #

    Когда два объявления претендуют на одно свойство одного элемента, браузер сравнивает их по критериям строго по порядку. До следующего критерия дело доходит, только если на текущем ничья.

    #КритерийЧто побеждает
    1Происхождение и важностьстили пользователя и !important в особом порядке (ниже); обычно — стили автора против стилей браузера (user-agent)
    2Контекстстили Shadow DOM против внешних — для веб-компонентов
    3Стиль в атрибуте style=""инлайн побеждает любые селекторы
    4Каскадные слои (@layer)для обычных объявлений побеждает более поздний слой; стили вне слоёв сильнее любого слоя
    5Специфичность(id, класс/атрибут/псевдокласс, тип/псевдоэлемент) — сравнивается слева направо
    6Порядок в кодепри равенстве — более позднее

    Главное следствие четвёртой строки: слои проверяются до специфичности. Правило .btn в слое components побеждает #main .speaker-list li .btn в слое vendor, если components объявлен позже. Так слои заканчивают войну специфичности: вместо «перебить селектором посильнее» — «положить в правильный слой».

    @layer reset, vendor, tokens, base, layout, components, utilities;   /* порядок объявляется один раз */

    .plan-featured .price(0, 2, 0)
    #main .speaker-list li h3(1, 1, 2)один id перевешивает любое число классов
    :is(#main, .x) h3(1, 0, 1):is берёт специфичность самого сильного аргумента
    :where(#main, .x) h3(0, 0, 1):where всегда обнуляет свои аргументы

    🔬 Под капотом: почему у !important порядок слоёв переворачивается

    !important — не «очень сильно», а переход в отдельный, зеркальный ярус каскада. Для важных объявлений порядок происхождения переворачивается (важные стили пользователя сильнее важных стилей автора — так человек с плохим зрением может навязать свой размер шрифта), и порядок слоёв тоже: важное объявление в раннем слое побеждает важное в позднем. Смысл — дать базовым слоям (reset, vendor) способ сказать «это нельзя переопределить случайно». Отсюда правило лабы: !important допустим только в утилитах вроде .visually-hidden, чей смысл — «всегда».

    4. Box model, нормальный поток и контексты форматирования #

    Без display: flex/grid элементы раскладывает нормальный поток (flow layout): блочные идут сверху вниз и занимают всю ширину, строчные текут в строке, как слова.

    ┌──────────────── margin ─────────────────┐
│ ┌────────────── border ───────────────┐ │
│ │ ┌──────────── padding ────────────┐ │ │
│ │ │            content              │ │ │   width (content-box) = только content
│ │ └─────────────────────────────────┘ │ │   width (border-box)  = content + padding + border
│ └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘

    Схлопывание margin

    Вертикальные (block-direction) margin соседних блоков в потоке не складываются, а схлопываются до большего: margin-bottom: 2rem и margin-top: 3rem дают 3rem. Коварный случай — margin первого ребёнка «проваливается» сквозь родителя без padding и border: h1 с margin-top внутри section с фоном сдвигает всю секцию вместо отступа внутри. Схлопывание отключается у flex- и grid-элементов, при padding или border у родителя и в новом контексте форматирования.

    Контекст форматирования блока (BFC)

    Изолированная область, внутри которой раскладка не влияет на внешнюю: margin не проваливаются наружу, float не вылезают. Создают его display: flow-root (специально для этого), flex- и grid-контейнеры, overflow не visible, position: absolute.

    Логические свойства

    margin-block, padding-inline, inset-inline-start, inline-size — вместо top/right/bottom/left и width/height. Привязаны к направлению письма: для арабского интерфейса (dir="rtl") padding-inline-start окажется справа сам. В лабе используем логические свойства по умолчанию.

    5. Раскладки: flow, Flexbox, Grid — когда что #

    FlexboxGrid
    Измеренийодно (ряд или колонка), перенос — отдельные строки без выравнивания между нимидва: строки и колонки одновременно
    Кто решает размерконтент: элементы растягиваются и сжимаются от своего размераконтейнер: сетка задаётся, элементы в неё встают
    Типичноешапка, кнопки в ряд, медиа-объект (картинка + текст), центрированиемакет страницы, карточки одинаковой ширины, таймлайн, выравнивание между карточками (subgrid)
    В FrontFestшапка (3.1), кнопки hero, карточка тарифа внутри (3.3)каркас страницы (4.1), спикеры (4.2), программа (4.3), тарифы (4.4)

    Эмпирическое правило: если вы задаёте ширины элементам, чтобы они встали в колонки, — нужен Grid; если элементы должны занять столько, сколько им нужно, а остаток поделить — Flexbox.

    Главные свойства

    .header { display: flex; align-items: center; gap: 1rem; }      /* flex-контейнер */
.header .theme-toggle { margin-inline-start: auto; }             /* «оттолкнуть вправо» */
.card { flex: 1 1 16rem; }                                        /* grow shrink basis */

.speakers { display: grid; grid-template-columns: repeat(auto-fill, minmax(15rem, 1fr)); gap: 1.5rem; }
.page { display: grid; grid-template-rows: auto 1fr auto; min-block-size: 100dvh; }
.session { grid-column: a; grid-row: t1000 / t1130; }            /* по именованным линиям */
    🔬 Под капотом: как flex делит место

    1) Каждому элементу берётся базовый размер flex-basis (или ширина контента при auto). 2) Считается свободное место = контейнер − сумма базовых. 3) Если место есть — оно делится пропорционально flex-grow. Если места не хватает — элементы сжимаются пропорционально flex-shrink × basis. 4) Но ни один элемент не сожмётся меньше своего минимального размера, а у flex-элементов по умолчанию min-width: auto — ширина самого длинного неразрывного слова или картинки. Отсюда баг шага 3.2: длинный URL не даёт колонке сжаться, и раскладка вылезает за экран. flex: 1 — это 1 1 0%: базовый размер ноль, всё место делится поровну, а не «поровну сверх контента».

    6. Адаптивность: intrinsic-дизайн, медиазапросы, container queries #

    Современный подход — сначала сделать раскладку, которая сама подстраивается под место (intrinsic design), и только потом добавлять точки перелома.

    ПриёмКакНужен ли медиазапрос

    Колонки «сколько влезет»repeat(auto-fill, minmax(min(100%, 15rem), 1fr))нет

    Медиазапрос против container query

    Медиазапрос спрашивает «какой ширины окно». Карточка спикера на главной (широкая сетка) и в боковой колонке программы (узкая) живёт в окне одной ширины, но места у неё разное. Container query спрашивает «какой ширины мой контейнер» — и компонент становится переносимым: один CSS, правильный вид в любом месте.

    .speaker { container-type: inline-size; }                 /* предок объявляется контейнером */
@container (inline-size > 24rem) {
  .speaker-card { grid-template-columns: 8rem 1fr; }       /* стилизуются потомки, не сам контейнер */
}

    Mobile-first: базовые стили — для узкого экрана, медиазапросы с >= добавляют сложность по мере роста места. Синтаксис диапазонов (width >= 48rem) в Baseline с 2023 года и читается лучше, чем (min-width: 48rem).

    7. Цвет и темы: oklch, color-mix, light-dark() #

    oklch(L C H) — цветовое пространство, где L (светлота, 0–100%) соответствует тому, как свет воспринимает глаз. В HSL жёлтый и синий с одинаковой «lightness 50%» выглядят совсем разной яркости; в oklch одинаковое L — одинаковая воспринимаемая яркость. Поэтому палитру и контраст удобно строить в oklch: меняем L — получаем оттенки, меняем H — получаем другой цвет той же яркости.

    --brand:        oklch(52% 0.2 295);                                  /* фиолетовый */
--brand-hover:  color-mix(in oklch, var(--brand), black 15%);        /* смешивание */
--brand-soft:   oklch(from var(--brand) 95% 0.04 h);                 /* относительный цвет: та же H, другие L и C */

    Тёмная тема без дублирования

    :root {
  color-scheme: light dark;                                          /* по умолчанию — как в ОС */
  --bg:   light-dark(oklch(98.5% 0.005 295), oklch(18% 0.02 295));
  --text: light-dark(oklch(22% 0.02 295),   oklch(93% 0.01 295));
}
:root[data-theme="light"] { color-scheme: light; }                  /* ручной выбор перебивает ОС */
:root[data-theme="dark"]  { color-scheme: dark; }

    light-dark(a, b) выбирает значение по вычисленному color-scheme элемента. Переключатель темы меняет одно свойство, и все токены переключаются сами. Бонус: color-scheme перекрашивает и то, что рисует браузер, — полосы прокрутки, поля ввода, чекбоксы.

Ловушка: на экране уже 18rem (288px при 16px шрифте, минус отступы) минимальная колонка шире контейнера, и появляется горизонтальный скролл на всей странице. min(100%, 18rem) — «18rem, но не больше контейнера». Разница auto-fill и auto-fit видна, когда элементов меньше, чем влезает колонок. auto-fill оставляет пустые колонки-заготовки, и две карточки остаются узкими. auto-fit схлопывает пустые колонки, и две карточки растягиваются на всю ширину. Для каталогов обычно нужен auto-fill: карточка не должна раздуваться, если результат поиска один.

    Шаг 6.3Анимация переходов между страницами: cross-document view transitions как прогрессивное улучшение#
    /* base.css */
@media (prefers-reduced-motion: no-preference) {
  @view-transition { navigation: auto; }            /* включить анимацию переходов между страницами сайта */
}

.logo { view-transition-name: site-logo; }          /* одинаковое имя на обеих страницах → элемент «перелетает» */
main h1 { view-transition-name: page-title; }       /* имя должно быть уникальным на странице */

/* своя анимация для остальной страницы: лёгкий сдвиг и растворение */
::view-transition-old(root) { animation: 0.25s ease-in both vt-out; }
::view-transition-new(root) { animation: 0.3s ease-out both vt-in; }
@keyframes vt-out { to { opacity: 0; translate: 0 -12px; } }
@keyframes vt-in { from { opacity: 0; translate: 0 12px; } }

    Переходите по ссылкам шапки между главной, программой и регистрацией в Chrome, затем в браузере без поддержки (Firefox, если там ещё нет).

    Зачем: обычный переход между страницами — белая вспышка и мгновенная смена. Cross-document view transitions делают снимок старой страницы, загружают новую и анимируют разницу. Элементы с одинаковым view-transition-name на обеих страницах «перелетают» из старого положения в новое, остальное растворяется. Всё это без SPA и без JS — многостраничный сайт из трёх HTML-файлов. Это чистое прогрессивное улучшение: браузер, который не знает @view-transition, игнорирует правило, и переходы остаются обычными. Отсюда же правило для любой новой возможности: сайт обязан работать без неё. Обёртка в prefers-reduced-motion: no-preference включает анимацию только тем, кто не просил уменьшить движение.

    12. Глоссарий #

    Каскад — алгоритм выбора одного значения из конкурирующих объявлений: происхождение и важность, контекст, инлайн, слои, специфичность, порядок.
    Специфичность — «вес» селектора: (id, классы/атрибуты/псевдоклассы, типы/псевдоэлементы).
    Каскадный слой — @layer: группа стилей с приоритетом, проверяемым до специфичности.
    Наследование — передача вычисленного значения свойства от родителя детям (для наследуемых свойств).
    Box model — content, padding, border, margin; box-sizing определяет, что входит в width.
    Нормальный поток — раскладка по умолчанию: блоки сверху вниз, строчные в строку.
    Схлопывание margin — объединение вертикальных margin соседних блоков в потоке до большего из них.
    BFC — контекст форматирования блока: изолированная область раскладки (flow-root, flex, grid, overflow).
    Логические свойства — block/inline-направления вместо физических сторон; зависят от направления письма.
    Custom property — CSS-переменная --x, наследуется и меняется в рантайме.
    Токен — именованное дизайн-решение (отступ, цвет, размер), хранящееся в custom property.
    clamp() — значение между минимумом и максимумом с «предпочитаемым» посередине.
    OKLCH — цветовое пространство: светлота, хрома, оттенок; одинаковая L — одинаковая воспринимаемая яркость.
    color-scheme — какую схему (светлую, тёмную) использует элемент; влияет на light-dark() и нативные контролы.
    Главная и поперечная оси — направления во flex-контейнере: вдоль flex-direction и перпендикулярно.
    flex-basis — базовый размер flex-элемента до распределения свободного места.
    Минимальный размер содержимого — ширина самого длинного неразрывного фрагмента; по умолчанию нижний предел flex-элемента.
    Grid-линия, трек, область — линии делят сетку на треки (строки, колонки); области — прямоугольники из ячеек.
    Неявная сетка — треки, которые grid создаёт сам, когда элемент размещён за пределами явной.
    fr — доля свободного места в grid-треках.
    Subgrid — сетка, берущая треки у родительской сетки.
    Full-bleed — элемент на всю ширину окна внутри ограниченной по ширине колонки контента.
    Intrinsic design — раскладка, подстраивающаяся под контент и место без точек перелома.
    Container query — условие на размер контейнера-предка, а не окна.
    :has() — псевдокласс «содержит», позволяет стилизовать элемент по его потомкам и соседям.
    :user-invalid — невалидное поле после взаимодействия пользователя.
    Контекст наложения — группа элементов, внутри которой сравниваются z-index; создаётся position+z-index, transform, opacity, isolation и др.
    Sticky — позиционирование, при котором элемент прилипает к краю ближайшего контейнера прокрутки.
    Composited-свойства — transform, opacity и т. п.: анимируются без пересчёта раскладки.
    @property — регистрация custom property с типом, начальным значением и наследованием.
    Baseline — статус поддержки возможности во всех основных браузерах (newly / widely available).
    Прогрессивное улучшение — возможность, без которой сайт работает, а с ней — лучше.
